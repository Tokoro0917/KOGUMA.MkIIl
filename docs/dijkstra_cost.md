# ダイクストラのコストを走行時間に合わせる(2026-10-26 調査)

九州地区大会(2026-10-25)のあと、最短の経路の選び方を見直すために調べたこと。
同じ日に機体に入れた(下の「機体に入れたもの」)。

## きっかけ

- 九州地区大会のクラシックの迷路(`mazes/2025_alljapan_classic.txt`)で、本番のダイクストラ(今の master)は南回り(43区画)を選び、最短 2.982 秒で優勝した
- PR #59(ダイクストラがいつもコストの最安を返すようにする修正)を入れると、同じ迷路で西回り(45区画、8区画の長い直線)を選ぶ。走行時間の見積もりでは南回りより約 0.07 秒遅い
- つまり今のコストの重み(直進の1歩目 `ST_COST` 5、斜めの1歩目 `DIAG_COST` 3、続けて進む `CON_COST` 2)は、KOGUMA の実際の速さを表していない。今の master は、#59 で直したくせ(来た向きの書き換えでコストがずれる)のおかげで、たまたま速いほうを選んでいた

## 走行時間の見積もり(`tools/route_time.py`)

最短の命令列(`G_Short_Pass_NANAME`)から、機体(`Move.c` の `Short_Dijkstra_Move2000`)と同じ動きで時間を数える。
直線は cos 型の加減速(縦横は加速 AC・減速 2×AC、斜めは AC−5000)、ターンは Turn-Sim と同じ計算で、ターンの形(角度・角速度・角加速度)だけで決まる時間(壁切れの位置に左右されない)。

| 確かめた走行 | 見積もり | 実際 |
|---|---|---|
| 九州地区大会 最短(2000、モード1 No.5、赤の経路) | 2.987 秒 | 2.982 秒(公式記録) |
| 10-20 練習の最短(8×6 の迷路、ログ `logs/20261020-154825`) | 1.299 秒 | 1.364 秒(ログ。止まる瞬間の判定で長めに出る) |

## 迷路(`tools/mazefile.py`)

[micromouseonline/mazefiles](https://github.com/micromouseonline/mazefiles) の `classic/` の 16×16 の迷路(ゴールが中央 2×2)、重複を除いて 510 個。
2025 全日本のクラシック(`alljapan-046-2025-exp-fin.txt`)は、大会の迷路図から読み取った `mazes/2025_alljapan_classic.txt` と壁が全部一致した。

## 調べ方

PR #59 のダイクストラ(同じ向きに k 歩進む区間をまとめて広げる)のコストを、PC 用に差し替えて経路を作り、見積もりの時間で比べた。
迷路ごとに、試したすべての重みと BFS・今のダイクストラの経路の中で一番速いものを「一番速い経路」とし、そこから何 ms 遅いか(損)を数えた。

## 結果(510 迷路、最高速 6000・加速 20000)

| 速度 | 方式 | 平均の損 | 一番大きい損 | 一番速い経路を選べなかった迷路 |
|---|---|---|---|---|
| 2000 | 今のダイクストラ(master) | 25.0 ms | 285 ms | 183 |
| 2000 | #59(重み 5,3,2,2) | 21.6 ms | 312 ms | 176 |
| 2000 | #59、重みだけ変える(一番よい 13,7,5,6) | 16.4 ms | 331 ms | 144 |
| 2000 | **#59、区間のコスト = 走行時間の表**(縦横 +15ms、斜め −10ms) | **2.4 ms** | 107 ms | 75 |
| 2400 | 今のダイクストラ(master) | 19.2 ms | 296 ms | 176 |
| 2400 | **#59、走行時間の表**(斜め ×1.1、斜め −10ms) | **2.1 ms** | 53 ms | 74 |

- 重みの数字を変えるだけ(1歩ごとに同じコスト)では、長い直線ほど1歩あたりが速くなる(加速)を表せず、改善は小さい
- 区間のコストを「その長さの直線を、ターンの速度 V から最高速まで上げて V に戻す時間」にすると、損が 1/10 になる。#59 は区間をまとめて数えるので、区間の長さごとに好きなコストを入れられる
- ターンの上乗せは 0 の近くがよい(ターンの区間を走る時間は、同じ距離を V で走る時間とほぼ同じ)
- 九州地区大会の迷路では、走行時間の表のダイクストラは 2000・2400 とも本番の赤と同じ経路を選ぶ

## 機体に入れたもの(2026-10-26)

- #59 のダイクストラ(区間ごとに広げる)を入れ、区間のコストを走行時間の表にした(`Maze.c` の `Maze_Dijkstra_Set_Speed()`、`G_Dijk_Inc_O` / `G_Dijk_Inc_D`)
  - 表[k] は区間の k 歩目のコスト(0.5ms 単位、1〜39。もっと長い区間は表[39])。区間のコスト = 表[1] + … + 表[k] ≒ k 歩の直線の時間 + 区間ごとの補正
  - 表は最短走行を始めるときに、ターンの速度・最高速・加速度・斜めの加速度から作る(`Short_Dijkstra_Move2000` は 2000、`Short_Dijkstra_Move2400` と `Short_Dijkstra_MoveTurnV` は 2400 の補正)。作る時間はほとんどかからない
  - 補正は、2000 が縦横 +15ms・斜め −10ms、2400 が縦横 0ms・斜め −10ms で斜めの時間を 1.1 倍
  - **k 歩目のコストは k−1 歩目より大きくしない**。斜めの補正がマイナスなので、そのままだと斜めの1歩目(99)が2歩目(106)より安く、「斜めの直線を途中で切って区間を2つにする」ほうが安く見えて、区間ごとに広げる方法が本当の最短にならない。こうしても結果はほとんど同じ(下の表)
- `G_Dijk_Time_Cost = 0` にすると以前のコスト(`ST_COST` / `DIAG_COST` / `CON_COST`)に戻る
- `DIJK_MAXCOST` を 2890 から 65000 に上げた(コストは uint16 のまま。16×16 では、1区画あたり多くても約 210 なので 256 区画でも約 54000)。32×32(PC の検証用)はコストを uint32 にする
- 未知壁探索のダイクストラ誘導(モード0 No.6・No.7・No.10)も、探索のあとの最短(モード1 No.5)と同じ 2000 の表を使う(`main.c` の `Maze_Search_Unknown_Walls()`)
- `test_shortpath` の参照実装を、状態を「壁の中点 + 来た向き + 同じ向きが続いた数」にして表のコストに合わせた。2000・2400 の表と以前のコストの 3 つで、ダイクストラの経路のコストが本当の最短と同じかを確かめる。表を単調にする処理を外すと失敗する(16×16 のループあり迷路 300 個中 23 個)
- `mazes/2025_alljapan_classic.txt` は、2000・2400 の表とも赤(南回り)を選ぶ。以前のコストでは西回り

表を単調にしたあとの結果(510 迷路。試した重みの数が上の表と違うので、損の基準が少しずれる):

| 速度 | 方式 | 平均の損 | 一番大きい損 | 一番速い経路を選べなかった迷路 |
|---|---|---|---|---|
| 2000 | 走行時間の表(単調にしない) | 2.1 ms | 107 ms | 72 |
| 2000 | **走行時間の表(単調にする、機体)** | **2.1 ms** | 107 ms | 71 |
| 2400 | 走行時間の表(単調にしない) | 2.0 ms | 53 ms | 72 |
| 2400 | **走行時間の表(単調にする、機体)** | **1.9 ms** | 53 ms | 68 |

Flash は約 1.1KB、RAM は約 160 バイト増えた(`Maze.o`)。
