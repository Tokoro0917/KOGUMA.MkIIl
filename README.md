# KOGUMA MkIIl

STM32F446RE(STM32CubeIDE)をベースにしたマイクロマウス(迷路探索ロボット)のファームウェア。

## ハードウェア

- MCU: STM32F446RE(Cortex-M4, Flash 512KB, RAM 128KB)
- 開発環境: STM32CubeIDE 1.14.0

## ディレクトリ構成

```
Core/Src, Core/Inc   本体ファームウェア
Drivers/             STM32 HAL / CMSIS
KOGUMA.MkII/          旧バージョン一式(参考用に同梱)
test/                ホスト(PC)上で走るテスト(迷路・距離変換・速度計画)
sim/                 PC上の探索シミュレータとブラウザ用の可視化
docs/                調べたことのメモ(他の人のターン速度の決め方など)
.github/workflows/   CI設定
*.ioc                STM32CubeMX設定
STM32F446RETX_*.ld   リンカスクリプト
```

`Debug/`(ビルド成果物)とホストテストの実行ファイルは`.gitignore`で除外している。

## 迷路探索アルゴリズム(`Core/Src/Maze.c`)

2種類の最短経路計算を実装:

- **`Maze_Shortest_Calculation()`**: セル単位のBFS歩数マップに基づく最短経路。直交移動のみ。
- **`Maze_Dijkstra_Calculation()`**: 半セル(壁境界)単位のグラフ上でSPFA(キューベースのBellman-Ford)を用いたダイクストラ法。直進・斜め・コーナー継続でコストを変え(`ST_COST`/`DIAG_COST`/`CON_COST`)、斜め走行を積極的に使う経路を生成する。境界ノードは「どちら向きに通過しているか」で2つの状態に分けてあり、進めるのは今の向きの先のマスを通る3本の辺(直進1・斜め2)だけ。

BFS版の経路をたどるときは、ゴール2×2区画の4マス全部を歩数0の起点にして歩数マップを作り直す(探索用の歩数マップはゴールの1マスだけが起点)。スタートからゴールへ行けないときは、どちらも空の経路を返す。

どちらも生成した手順を`Shortest_Pass_Compression()` → `Shortest_Pass_Compression_NANAME()`で圧縮し、コーナーの大廻り・斜め入り/出のパターンに変換してから`Move.c`のモーター制御関数(`Short_NANAME_Move*`/`Short_Dijkstra_Move2000`など)が実行する。

ゴールは迷路中央の2×2区画(標準ルール)。どの面が開口になっているか大会では事前に分からないため、ゴール判定(BFS・ダイクストラとも)は2×2区画を囲む境界のどこから侵入しても「到達」とみなすようになっている。

### 行き止まり潰し(`Maze_DeadEnd_Fill()`)

確認済みの壁だけで出入口が1つ以下になったマスは、入った辺と同じ辺からしか出られないため、そのマス自身が始点/終点でない限り最短経路上に絶対に乗らない。エセ全面探索(ALL_MODE)は未探索マスを片端から目標にするので、放っておくとこうした袋小路のポケットにも寄り道してしまう。

`Maze_DeadEnd_Fill()`はそういうマスを`G_MAZE_Closed[][]`に記録し、**連鎖させる**。1マス閉じるとそのマスは隣にとって「出口」として数えられなくなるので、袋小路の通路が根元まで一気に潰れる。`Maze_Gool_Setting()`は閉鎖マスを全面探索の目標候補から外す。

呼び出しは`Maze_Wall_Update()`の4方向分岐、`Maze_Step_Calculate()`の直前。

安全側に倒すための作りが要点:

| 方針 | 理由 |
|---|---|
| `G_Maze_Row`/`G_Maze_Column`(実測の壁マップ)を書き換えない | マップの保存・表示・ダイクストラは今まで通り真の壁だけを見る |
| 閉鎖情報を歩数マップBFSの通行判定に使わない。使うのは目標選定だけ | 誤って閉じても起きるのは「そのマスを探索しない」だけ。経路が塞がる/帰還できなくなる経路が構造的に存在しない |
| 毎回ゼロから再計算(ステートレス) | 誤った閉鎖が累積しない。探索用⇔帰還用のゴール切り替えにも自動追従 |
| 未確認の壁は「開いている」とみなす | 既知の壁 ⊆ 真の壁 なので、探索途中の部分知識では完全知識より必ず閉鎖数が少なくなる |
| スタート・現在の目標・ゴール2×2区画は閉じない | スタートは初期状態で3枚壁。守らないと即座に潰れて帰還できなくなる |

`G_DeadEnd_Fill_Enable`を`0`にすると実行時に無効化でき、従来動作に戻る。閉鎖したマス数は`g_deadend_closed_count`で確認できる(`Maze_Mapping()`内にコメントアウト済みの可視化用printfあり)。

副次的な効果として、壁で完全に囲まれた到達不能マスは出入口0で必ず閉鎖されるため、ALL_MODEが通常の「未探索マス数が0」の経路でクリーンに終了するようになった(従来は「自分のマスがMAX_STEPのまま」を検出するフォールバック頼みだった。フォールバック自体は保険として残してある)。

### 迷路サイズ

`Core/Inc/Define.h`の`MAZE_SIZE`(既定16)を書き換えるだけで16×16⇔32×32を切り替えられる。壁ビット幅・ノード配列サイズ・キュー容量・ゴール座標は全てこの値から自動的に導出される。

16×16の現在のビルド(Debug、arm-none-eabi-gccでの確認)はFlash約107KB、RAM(data+bss)約112KB/128KB(2026-10-07)。32×32はこのままではRAMに入らない。ダイクストラはノードを向きごとの状態に分けたため、作業領域が16×16で約9KB、32×32で約35KBある。32×32を実際に有効化する場合は、`Core/Src/LOG.c`の`LOG_MAX`(現在2000、既定3000から削減済み)を含めたRAM予算の再確認が必要。

### モード0: 大会用(探索走行)

往路(スタート→ゴール)のあと、片道ならゴールで止まり、それ以外はスタートへ戻る。区間の終わりごとに`Maze_Save()`する。No.8〜10はスタートに戻ったあと2秒待って最短走行(モード1 No.5と同じ: ダイクストラ、コーナー2000、直線6000mm/s、加速20000)まで走る。中身は`main.c`の`Maze_Search(flags)`で、番号ごとに`SEARCH_*`の組み合わせを指定している。

| No | 走り方 | 復路 | `SEARCH_*` |
|---|---|---|---|
| 0 | (何もしない) | | |
| 1 | スラローム探索(500mm/s、吸引なし) | 往復 | `SLALOM` |
| 2 | スラローム探索 | 往復、復路で**エセ全面探索** | `SLALOM \| ALL` |
| 3 | スラローム探索 | **片道**(ゴールで止まる) | `SLALOM \| ONEWAY` |
| 4 | 吸引探索(1000mm/s、吸引あり) | 往復 | `SUCTION` |
| 5 | 吸引探索 | 往復、復路で**エセ全面探索** | `SUCTION \| ALL` |
| 6 | 吸引探索 | ゴール後に**ダイクストラ誘導の未知壁探索**、終わったらスタートへ | `SUCTION \| DIJKSTRA` |
| 7 | 吸引探索+**既知区間加速** | No.6と同じ | `SUCTION \| DIJKSTRA \| KNOWN` |
| 8 | スラローム探索 | 往復 → **最短** | `SLALOM \| SHORTEST` |
| 9 | 吸引探索 | 往復 → **最短** | `SUCTION \| SHORTEST` |
| 10 | 吸引探索+**既知区間加速** | No.6と同じ → **最短** | `SUCTION \| DIJKSTRA \| KNOWN \| SHORTEST` |

片道(No.3)はゴール区画に入ったところで、Uターンのときと同じ減速(70mm)で止まる。

既知区間加速(`Robot_Maze_Pass_Action()`)は、次の区画が探索済みなら、未探索の区画の手前までを`Known_Pass_Generation()`でまとめて経路にし、直線を最大4000mm/sで走る。

ダイクストラ誘導(No.6/No.7/No.10)は往路でゴールに着いたあと、スタート→ゴールのダイクストラ経路上に残っている未確認の壁を、今いる位置から直接見に行く(`Maze_Unknown_Wall_Scan()`)。経路の再計算は毎回ではなく、ゴールに着いた直後とUターンしたときだけ行い、どちらも**機体が区画の中央で止まっているあいだに**計算する。ゴールに着いた直後は次の区画の中央で止まって計算してから、進む向きを決めて発進する(`Robot_Maze_Stop_And_Go()`)。Uターンでは止まっているあいだに計算し(`G_Stop_Hook`)、行き止まりでなければ計算した結果で進む向きを決め直す。壁を1枚確認できたら、ダイクストラは計算し直さず、同じ経路で次の未確認の壁を探す。経路上の未知壁がなくなったらスタートへ帰る。

エセ全面探索(`Maze_Unkown_ALL_ModeSet()`)が有効なのは**No.2・No.5だけ**。したがって**行き止まり潰しが走行に影響するのもこの2つだけ**(`Maze_DeadEnd_Fill()`自体は常に計算されるが、結果を使う`Maze_Gool_Setting()`の分岐がALL_MODE時にしか通らないため)。

| 2 | BFS | 2000 | 20000 | `Short_NANAME_Move2000` |
| 3 | BFS | 2400 | 20000 | `Short_NANAME_Move2400` |
| 4 | ダイクストラ | 2000 | 15000 | `Short_Dijkstra_Move2000` |
| 5 | ダイクストラ | 2000 | 20000 | `Short_Dijkstra_Move2000` |
| 6 | ダイクストラ | 2000 | 23000 | `Short_Dijkstra_Move2000` |

| 8 | ダイクストラ | 2400 | 20000 | `Short_Dijkstra_Move2400` |

コーナー2700(`Short_NANAME_Move2700`)の関数は残してあるが、今はどの番号からも呼んでいない(実機で走れていない)。

### ターンごとの通過速度(`Short_NANAME_MoveTurnV`、モード1 No.10・No.11)

2400は一番きついターン(V90)に合わせた速度なので、横加速度に余裕のあるターンは速く、きついターンは遅く回る。`Short_NANAME_Move2400`と同じ走り方で、ターンの種類ごとに通過速度を持つ(2026-10-07に2000基準から2400基準に作り直した。調べたことは`docs/turn_speed_research.md`)。

- 速度は`Move.c`の`TurnV_Table`の`v`で設定する。左右は同じ値を使う。**`v`を全部2400にすると`Short_NANAME_Move2400`と同じ走りになる。**
- 旋回のパラメータ(角度・角速度・角加速度・前距離・後距離)は`Short_NANAME_Move2400`の値を基準にして、通過速度Vに合わせて角速度を V/2400 倍、角加速度を (V/2400)² 倍にする。理想的には同じ軌跡(同じ旋回半径)で、横加速度が (V/2400)² 倍になる。前後のオフセット距離は理想的には変わらないが、実機では滑りや遅れで変わるので、速度を変えたターンは`offset_st`/`offset_end`を調整する(モード10 No.1〜7)。
- 走り出しは`Short_NANAME_Move2400`と同じ(最初が直線ならスタート区画の境目までに加速、最初がターンなら`G_First_Turn`のターンごとの速度で曲がって後距離で加速)。ゴール停止区間の入口は2400が上限。斜めの直線の加速度は`AC - 10000`(2400と同じ)。

速度のつなぎ方(`Core/Src/SpeedPlan.c`):

- **間に直線があるとき**: 後距離はそのターンの速度で一定に走り、直線で次のターンの速度に合わせる。直線が短くて加減速しきれなければ、その範囲までターンの速度を下げる(motor.cのcos加減速の距離の式で、直線の9割で収まるようにする)。
- **ターンが直線を挟まずにつながるとき**: 前のターンの後距離のうちに、次のターンの速度へ加速度30000(`TURNV_AC_BACK`)で変える。後距離が壁切れで早く終わることがあるので、後距離の8割(`SPEEDPLAN_BACK_MARGIN`)で変えきる。次のターンの前距離は、そのターンの速度で一定に走る。変えきれないときは、変えきれる速度まで速い方のターンを下げる(遅い方にそろえることはしない)。
- 後距離で速度を変えるのは`Motor_Wallcut_END_Accel`/`Motor_Wallcut_END_NANAME_Accel`(最初のターン用に作ったもの。減速もできるようにした)。

速度の初期値と考え方。`Short_NANAME_Move2400`のパラメータで見積もったピーク横加速度(速度2400、角速度が三角形になる場合の頭打ちを考慮)が一番大きいのはV90。**V90の限界を2200とすると**、限界の横加速度は約91.5m/s²(9.3G)で、ほかのターンがそこに届く速度は次のとおり。

| ターン | 2400での横加速度[m/s²] | 限界に届く速度 | 初期値(`TurnV_Table`) |
|---|---|---|---|
| V90 | 109 | 2200(基準) | 2200 |
| 斜め入り45 | 90 | 約2420 | 2400 |
| 斜め出135 | 88 | 約2450 | 2400 |
| 斜め入り135 | 84 | 約2510 | 2400 |
| 大回り90 | 67 | 約2800 | 2600 |
| 大回り180 | 63 | 約2900 | 2500 |
| 斜め出45 | 59 | 約2980 | 2600 |

- 伸ばせるのは大回り90・大回り180・斜め出45。2700(`Short_NANAME_Move2700`)の大回り90は約94m/s²、V90は約132m/s²で、限界を超えている(2700で走れなかったことと合う)。
- 大回り180はほかの人も遅めにしているので、初期値を特に控えめにした。
- 斜め出45は後距離が40mmしかないので、上げすぎると斜め入りに続く場所で下げられる(2980→2420は加速度30000では変えきれない)。
- この見積もりは「限界は横G(滑り)で決まる」という仮定に立っている。V90が怪しい原因が柱や壁の補正なら、V90を基準にした表は当てはまらない。

ランダム迷路1000個(ダイクストラ、ループ30本)の経路で、初期値のときにターンが表の速度のまま回れる割合は 大回り90 91%、大回り180 94%、斜め出45 83%、ほかは100%。2400未満に下がるターンはない(V90は表で2200)。

### 迷路の出力(モード3 No.0、`Maze_Debug_Dump()`)

## 壁センサの距離変換(`Core/Src/WallDistance.c`)

壁センサの値は距離に比例しない(近いほど急に大きくなる)。センサ値の差をそのまま制御に使うと、壁に近いときはゲインが効きすぎ、遠いときは効かなくなる。また左右のセンサで感度が違うため、`(L - 220) - (R - 200)`は単位の違う数どうしの引き算になる。`WallDist_mm(sensor, value)`はセンサ値を距離[mm]に変換する(表引き+直線補間)。

距離の定義: 横センサは機体の中心線から横壁の表面まで、前センサは機体の中心から前壁の表面まで。区画中心ではどちらも84mm。

**横(L/R)は実測値**(2026-10-06)。機体の側面を反対側の壁につけ、壁の板(12mm)を n 枚はさんで、測る側の壁までを 133 − 12n mm(n = 0〜8、37〜133mm)にして測った(区画の内のり168mm、機体の幅70mm)。区画中心付近(85mm)で L=237、R=201。**前(FL/FR)も実測値**。お尻を後ろの壁につけ、板を n 枚はさんで前の壁までを 108 − 12n mm(n = -8〜4、60〜204mm。n が負はお尻を後ろの壁から離した)にして測った(全長120mm、中心からお尻まで60mm)。区画中心(84mm)で FL=645、FR=627。60mmより近い点はまだ測っていない(表の範囲外は端の値になる)。

### キャリブレーション手順(モード3 No.4)

1. モード3 No.4を選び、前センサに手をかざしてから横センサに手をかざしてスタートする
2. 約0.2秒ごとに`CAL,FL,L,R,FR,FL_mm,L_mm,R_mm,FR_mm`の形式でシリアル出力される(センサ値は100回平均、`_mm`は現在の表で変換した距離)
3. 横センサ: 機体を横にずらし、壁までの距離を44, 54, …, 124mmに合わせてL/Rの値を記録する
4. 前センサ: 前壁までの距離を34, 44, …, 174mmに合わせてFL/FRの値を記録する
5. `WallDistance.c`の表に書き写し、`test/test_walldist.c`を実行して表の並びが正しいか確認する
6. もう一度モード3 No.4で、`_mm`の列が実際の距離と一致するか確認する

手で機体を動かすとエンコーダのモード選択が変わるが、キャリブレーション中はループの中にいるので影響しない。終了はリセット。

### 会場ごとの感度合わせ(モード3 No.5)

会場では壁の反射の強さ(塗装)が変わり、センサ値が全部の距離でほぼ同じ割合で変わる。表は作り直さず、区画中心で1回測った倍率で合わせる。

1. モード3 No.5を選び、前センサに手をかざしてから横センサに手をかざしてスタートする
2. 機体を区画中心に置き、前・左・右に壁がある状態にする(スタート区画なら、後ろの壁のほうを向けて置く)
3. 約1秒ごとに、500回平均した値と、書き写す行がシリアルに出る
   - `WallDistance.c`の`WallDist_Scale`(倍率 = 測った値 / 表の区画中心の値。距離変換はセンサ値をこれで割ってから表を引く)
   - `Wallsensor.c`の`Wall_L`/`Wall_R`/`FlontWall_Distance`(区画中心の値そのもの)と`Wall_threshold`
   - `Move.c`の`ALIGN_FRONT_MIN`、`motor.c`の`Cut_R`/`Cut_L`/`Cut_R_NA`/`Cut_L_NA`
4. 出た行を手で書き写してビルドし直す。終了はリセット

閾値は「倍率1のときの値 × 倍率」で出す。基準の値は`Wall_Center_Calibration()`の中にある(2回目以降も、書き写したあとの値ではなく基準の値に掛ける)。閾値の基準を変えたら、ここも直す。

### 横壁制御の距離化(`G_WallCtrl_Use_mm`)

`Wallsensor.c`の`G_WallCtrl_Use_mm`を1にすると、`calWallConrol()`の誤差を`(84 - 距離)`[mm]で計算する。2026-10-07から既定は1。距離版では、壁まで`WallCtrl_mm_MaxDist`(104mm)以内の壁だけを使い、片側の誤差を±`WallCtrl_mm_ErrMax`(20mm)で頭打ちにし、切れ目の判定は1msの変化`Sensor_diff_TH_mm`(25)。0に戻すと従来のセンサ値版になる。ゲイン`Kp_mm`/`Kd_mm`の初期値は、区画中心付近で従来の`Kp`/`Kd`と同じ効きになる値(仮の表での傾き約5.2[値/mm]を掛けたもの)。表を変えたら調整し直す。

## テストとCI

`Core/Src/Maze.c`はHALに依存しないので、ホストのgccにそのままリンクして迷路アルゴリズムを検証できる。

```sh
# 16×16
gcc -std=c11 -Wall -I Core/Inc -o test_deadend test/test_deadend.c Core/Src/Maze.c && ./test_deadend
# 32×32
gcc -std=c11 -Wall -DMAZE_SIZE=32 -I Core/Inc -o test_deadend32 test/test_deadend.c Core/Src/Maze.c && ./test_deadend32
```

`test/test_deadend.c`が行き止まり潰しについて検査する内容:

| # | 内容 |
|---|---|
| 1 | 完全迷路(全域木)200種。連鎖が根元まで効いているか、最短経路上のマスが1つも潰れていないか、スタートとゴール2×2区画が守られているか |
| 2 | ループあり迷路300種。閉鎖マスを通行不可としても最短距離が変わらないか |
| 3 | 壁を4割「未確認」に落とした探索途中の状態300種。部分知識でも同上 |
| 4 | 初期状態(外周のみ既知)で1マスも閉じないか(誤爆検出) |
| 5 | `G_DeadEnd_Fill_Enable`による有効/無効の切り替え |

1〜3では、素朴な「変化がなくなるまで全マス走査」で書いた**参照実装**と閉鎖集合が完全一致するかも突き合わせている。仕様そのものの正しさは最短距離不変の検査が、連鎖機構(ワークリストの積み忘れ・打ち切り)のバグは参照実装との一致が担保する役割分担。

テストは不変条件が壊れると非0で終了する。実際に`Maze_Cell_IsProtected()`の保護を外した改変版を通すと失敗を検出することを確認済み。

  - ターン単体を表の速度で走るモード10 No.1〜7を追加
- **他の人のターン速度の決め方・前後距離・速度のつなぎ方の調査メモを`docs/turn_speed_research.md`に置いた**

- **最初のターンの速度をターンごとにした**(大回り90 1500、斜め入り45 1570、斜め入り135 1900)。最初のターンのすぐ後がまたターンの経路(最初がターンの経路の約8割)でも、後距離のうちに2400まで上がりきるようにした。`G_First_Turn`に速度の列を足した
- **最初のターンで180°回って壁に当たる不具合を修正**。先頭の -1(圧縮で0になった直線)をターンとして読み、大回り180として曲がっていた。先頭の -1 を飛ばすようにし、`test/test_shortpath.c`に最初の命令の形の確認を足した
- **`WallDist_Scale`を実機で測った値(1.01, 0.99, 1.02, 1.06)にした**。`test/test_walldist.c`は倍率を1にして表そのものを確かめるようにした
- **最短走行の最初のターンを調整するモードを追加**(モード4 No.9〜No.11、右大回り90・右斜め入り45・右斜め入り135)。パラメータは`Move.c`の`G_First_Turn`(前距離・角度・最大角速度・角加速度・後距離・速度)にまとめた
- **最短走行で最初が直線のとき、スタート区画の境目まで(114mm)なめらかに加速するようにした**(`Move.c`の`Short_Start()`)。加速度は π V² / (4 × 114)(2400で約39700)。最初がターンのときは、最初のターンだけ専用の速度(`G_First_Turn`、1000のターンの軌跡を速度に合わせたもの)で曲がり、後距離で最高速へ加速する(`Short_First_Turn()`、加速度`SHORT_FIRST_AC`、詳細はTODO.md)。次の直線は後距離の終わりの速度から、最高速に届くまで同じ加速度で加速する(`Short_Catchup()`)
- **横壁制御を距離版(`G_WallCtrl_Use_mm = 1`)に切り替えた**。対策後の直進テストのログで、角速度の振れが最大 +67/−85°/s(センサ値版は +175/−118°/s)だった。探索・最短走行もすべて距離版になる。モード4 No.8 はセンサ値版で走る(比較・切り戻し用)
- **距離版の横壁制御(`G_WallCtrl_Use_mm = 1`、モード4 No.8)の揺れ対策**。ログで比べると、遠い壁や壁の切れ目でセンサ値版の約2倍のキックが出ていた(遠い壁ほどmmの誤差が大きくなるため)。距離版だけ次のようにした(センサ値版は変えていない)
  - 壁まで`WallCtrl_mm_MaxDist`(104mm、区画中心から±20mm)より遠い壁は使わない
  - 片側の誤差を`WallCtrl_mm_ErrMax`(±20mm)で頭打ち
  - 壁の切れ目の判定を1msの変化25(`Sensor_diff_TH_mm`、センサ値版は50)に
  - 壁の有無が切り替わった瞬間はD項を出さない
- **横壁制御のD項が左のモーターにしか効いていなかった不具合を修正**。`calWallConrol()`は1msに3回(左PWM・右PWM・ジャイロ目標)呼ばれ、2回目以降は前回の誤差が更新済みでD項が0になっていた。計算を`Wall_Control_Update()`で1msに1回だけ行い、3か所で同じ値を使うようにした
- **直進中のジャイロ側の横壁制御の向きが、直前のターンで逆になっていた不具合を修正**。ジャイロPIDの目標の符号を`Turn_Mode`(最後のターンの向き)で決めていたため、左ターンのあとは壁に寄る向きに効き、左右のPWMへの横壁制御と打ち消し合っていた。直進中(`G_Motor_Flag == 1`)は常に壁から離れる向きにした
  - どちらも直進の壁制御の効きが変わる(左ターンのあとは強くなる)。モード4 No.1でふらつきを見て、必要なら`Kp`/`Kd`を下げる
- **モード4 No.8を追加**。No.1と同じ直進を、横壁制御を距離[mm]で(`G_WallCtrl_Use_mm = 1`、ゲインは`Kp_mm`/`Kd_mm`)走る。No.1と比べるため
- **ログに横壁制御の誤差と出力を追加**(列の最後に2列)。RAMは16×16迷路で約101KB/128KB。32×32迷路のビルドは、追加前から約4KB足りない

### 2026-10-06(実機確認で見つかったもの)

- **探索のスラロームで、前壁があるとき境目からすぐターンしていた不具合を修正**。ターン前の直進(`Motor_Sula_before`/`Motor_Sula_ST`)は前センサの平均が130を超えると打ち切っていたが、130は前壁まで約180mmで、境目(174mm)ではもう超えていた。前センサの値を距離に変換し、前壁までが`174 - 前距離`mmになったところでターンに入るようにした(前壁なしのときは今までどおり)。行き止まりのUターンや止まって計算するときも、区画中央で止まるようになる
- **既知区間加速で直線が半区画伸びる不具合を修正**。`Known_Pass_Generation()`に最短走行用の終端処理が入っていて、既知区間の最初に毎回90mm余分に直進し、最後の小回りが大回りになっていた(既知区間加速を使う探索)。元の動作に戻した
- **壁制御の目標値を実測の区画中心の値に変更**。横壁制御`Wall_L`/`Wall_R`を220/200→243/206、前壁合わせ`FlontWall_Distance`を530→636。以前は片側の壁だけのとき中心から数mmずれた位置に、前壁合わせでは区画中心より約8mm手前に合わせていた
- **ダイクストラ誘導の未知壁探索で、ダイクストラを機体が止まっているときだけ計算するようにした**。以前はゴールに着いた直後とUターンのあとに、1000mm/sで走りながら計算していた(約9ms、約1cm伸びる)
- **Uターンの位置合わせで、壁のない方向に前壁合わせをして急に前進する不具合を修正**。`Robot_adjustment()`(左90°×2)の2回目の前壁合わせを、元の左の壁で判定するようにし、合わせる前に今の前センサの値(`Wall_Flont_Av() > 200`)でも壁を確かめるようにした。吸引探索のゴール後の最初のUターンからログ(`LOG.c`)を取る仕組みも入れた(モード4 No.7で出力)
- **モード1の番号を並べ替え**、`main.c`の`Maze_Shortest_Run()`にまとめた。No.1〜3がBFS、No.4〜9がダイクストラ。ダイクストラのコーナー2400(`Short_Dijkstra_Move2400`)を追加。コーナー2700とターンごとの通過速度はモード1から外した
- **モード0の番号を並べ替え**、探索の流れを`main.c`の`Maze_Search()`にまとめた。探索のあとに最短まで走るものはNo.8〜10にまとめた(最短はどれもモード1 No.5と同じ)。スラローム片道(No.3)、既知区間加速なしのダイクストラ誘導(No.6)、スラローム往復→最短(No.8)を追加
- モード3 No.0の出力に、主な迷路計算の最大時間(`TIME_MAX_US`、実機のみ)を追加。実測(Debugビルド -O0)はダイクストラ約9ms、壁の記録+歩数マップ約2ms、歩数マップ約1.5ms

### 2026-10-05(PCでの検証で見つかったもの)

- **ダイクストラの経路が壁に突っ込む不具合を修正**。境界ノードが通過の向きを持っていなかったため、あとから向きが入れ替わったノードの先に古いつながりが残り、「マスに入って横へ抜け、同じマスに戻る」走れない経路ができていた(ランダム迷路5000個中4個)。ノードを向きごとの状態に分けて書き直した
